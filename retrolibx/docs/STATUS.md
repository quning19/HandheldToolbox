## 当前实现

- 保留Adapter→Library→ExportIntent→Planner→Executor架构，多前端及一游戏多ROM能力保持。
- ES-DE只导出封面、Logo、视频，保留子目录，不处理mini、缩放或转码。ROM留原处。
- 新增游戏子目录封面：从含有现存 ROM 的目录中选取有效游戏封面，按 ES-DE 目录媒体规则补齐各级文件夹图片。只增加媒体复制项，不增加游戏条目或 folder link；10个局部用例通过，GT78 已执行 GBA hack 和 PS1 的补齐，显示由用户验收。
- 共用素材默认关闭；明确开启后核对副本，按原字节局部更新metadata，再清理对应源媒体。其他字段、注释、编码及换行保留；仍被引用的源文件不删。
- 平台维护基线是主题工具完整四文件/76系统。设备快照可保留已有节点和追加平台；GT78当前77系统，含PSP Minis。
- 列表合并保留原非空字段、收藏、统计及额外记录。旧ROM根和旧系统目录名用显式配置，不自动盘点或猜测。
- 一次多平台`build`生成一个媒体脚本、完整配置和各平台列表，UTF-8/LF由现有Executor统一写出。
- `system_templates`明确复用现有/基线节点；`metadata_launch_systems`明确转换来源Android启动配置，未支持的形式报告错误，不执行来源命令。已有节点位置与ROM路径写法保留。
- C2上传完整目录内容，C4上传单文件到完整文件名。Unicode参数和POSIX路径引用保持；不自动清理远端。
- `deploy`复用upload/publish，默认本地预览，可选择upload/copy/publish或全部。设备脚本只有set -e、mkdir、cp；XML备份发布和可选共用清理由电脑端ADB执行。阶段结果、耗时及失败记录留本地，同任务分步记录保留。
- 生成/拷贝、专项资源检查、异常修复、测试分别授权。执行自然暴露问题时报告受影响项，不顺带筛除、修改捕获副本或重建整批。
