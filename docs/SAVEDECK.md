# SaveDeck 导出

游戏库页面选择 **SaveDeck**，再选择电脑上的天马 G 目录或通过 ADB 连接的 Android 掌机目录，点击“加载平台”，勾选平台后执行导出。

## 目录与流程

采用共用原目录的方式：在各平台 `metadata.pegasus.txt` 同级新增或更新 `savedeck.toml`，并生成官方编辑器命名的媒体。ROM 和天马 metadata 保留原样，不复制 ROM、不执行来源启动命令。原始媒体不清理；需要时增加 `cover.<原扩展名>`、多版本媒体目录等官方格式副本，已在相同位置的媒体直接共用。

```text
天马游戏库/
└── GBA/
    ├── metadata.pegasus.txt
    ├── savedeck.toml
    ├── 游戏.gba
    └── media/游戏/
        ├── boxfront.png        原素材保留
        └── cover.png           SaveDeck 使用的同内容副本
```

电脑来源点击“导出到原目录”，在工作目录生成媒体与配置后发布到原平台。设备来源点击“导出并推送”，在电脑生成配置，通过 ADB C4 上传；媒体在设备内直接复制到官方格式的目标文件名。设备来源捕获配置、CUE／GDI／M3U／CCD 等描述文件正文和文件名索引，不下载二进制 ROM 或媒体，空索引文件不会作为媒体上传。

每次导出的副本、计划和 manifest 保存在工作目录 `backups/library/savedeck-export-*` 批次中（具体路径以结果为准）；设备任务另存明确选择的媒体复制清单。源游戏库只发布所选媒体、`savedeck.toml` 和必要的旧配置备份，不写导出 manifest。

首次发布后，在 SaveDeck 的“设置 → SaveDeck游戏库”中绑定天马游戏库根目录；之后更新配置，在 SaveDeck 中刷新游戏库。此工具不操作 SaveDeck 应用的绑定或刷新。

## 字段与合并

- 平台名称采用来源 collection；平台默认命令写入顶层 launch，游戏独立命令写入对应 games 条目的 launch，核心、参数和路径保留，多行命令整理为单行。没有独立命令的游戏使用平台默认命令；官方导出成品也采用这一结构。
- 原简介保持原意及换行，不套用 ES-DE profile 的版本说明追加；developer、原素材引用等按官方保留为 `x_pegasus_*` 字段。
- 使用独立 `pegasus-g-savedeck` 来源 profile，继续保留官方字段别名和简介规则；媒体发现与 ES-DE 共用从 PegasusGGameManager 适配的实现。按用户决定，失效／未填引用都按目录优先级补找，同级多个候选选第一个并报告，因此媒体选择不再承诺与官方编辑器 1.0.1 完全一致。
- 先统计每个游戏实际存在的 file：仅一个存在时使用原游戏名；多个存在时使用“原游戏名 · ROM 文件名（去扩展名）”，与官方编辑器的组合方式一致；没有存在入口时不生成条目。不是将 ROM 相对路径的斜线替换为分隔符。媒体路径使用对应显示名，ROM 文件本身不改名。M3U、CUE 等入口路径保持原样。已有有效条目的名称默认保留，勾选“全量覆盖”后应用新命名，UUID 继续按 ROM 路径保留。
- 新条目生成小写 UUID v4；同一来源捕获中的 ID 固定。重复发布按 ROM 相对路径匹配，目标已有 UUID 不变。
- 按天马 `sort-by` 排序，未填时按游戏名；相同排序值保留原记录顺序，同一游戏内保留 `files` 顺序，再为有效入口生成连续六位 `sort` 并按此顺序写入 TOML。默认与全量都刷新排序；默认仍跳过有效旧入口的其他资料和媒体，仅新增并移除失效入口。全量以来源重建资料、媒体引用和 launch，来源不再提供的旧管理字段清除。两种模式均保留匹配入口的 ID、收藏、统计及未知目标扩展字段。未登记、缺失或成为从属文件的旧条目都会移除。
- TOML 使用 UTF-8、LF、官方的字段次序及字符串排版；不保留用户原注释。此前三平台样本在旧规则下完成官方成品对齐；当前缺失入口筛选和普通多版本名称按用户规则生成，历史比对记录见文末。

未填写 ROM 引用、路径重复、非法配置或平台外媒体会报告对应平台问题。根据用户在 SaveDeck 前端中的观察与确认，本工具仅将实际存在的 ROM 文件写入 TOML；缺失入口报告警告并排除，其对应媒体也不生成。多个 file 按入口分别判断，并按实际存在数量命名。合并已有 TOML 时也排除 ROM 不存在的旧条目，不删除旧媒体或改写天马 metadata。本工具仍共用原 ROM，不复制 ROM。

读取描述文件的明确关联，递归排除被 M3U／CUE 等引用的盘文件和轨道；不核查依赖完整性、不猜盘组。设备来源使用当次捕获的文件名索引。媒体显式引用存在时保持；失效或未填时依次查找原目录、游戏名目录、实际存在的 ROM 名目录及同游戏其他原有有效媒体所在目录。无引用时跳过原目录，同级候选按完整路径排序，选第一个并报告多候选情况；目录读取未知时不自动选择。只改变导出引用，不修改原天马 metadata。详见 [共用来源规则](engine/SOURCE_PROFILES.md#媒体)。封面和视频以外的原字段通过 `x_pegasus_*` 保留，来源模型中的 Logo 不额外输出为 SaveDeck 资源。

SaveDeck 规定 `file`、`cover`、`video` 必须在平台目录内，不能用绝对路径、网址或 `..`。当前只处理平台内来源媒体，不自动迁入外部 ES-DE 目录中的资源。

## 新增、删除与重复执行

每次资源发生变动后重新“加载平台”，再对所选平台导出；当前不是后台监控或自动同步。

| 来源变化 | 下一次导出的处理 |
|---|---|
| 新 ROM 已在天马 metadata 中登记 | 追加 TOML 条目，生成新的 UUID 和对应媒体 |
| 只增加 ROM，没有 metadata 记录 | 不自动补录，也不猜测资料或启动命令 |
| ROM 文件删除，metadata 记录仍在 | 排除该入口；若旧 TOML 已有对应条目，同样移除 |
| 同一游戏只有部分 file 被删除 | 逐入口判断，只保留仍存在的版本 |
| 只删除 metadata 记录，ROM 仍在且旧 TOML 已有条目 | 移除对应 TOML 条目，不删除 ROM 或媒体 |
| ROM 路径改名并同步修改 metadata | 作为新入口追加；旧路径已不存在时移除旧条目，不自动沿用旧 UUID |

重复导出以 ROM 相对路径匹配条目，保留已有 UUID；默认跳过有效旧条目的资料与媒体，排序始终跟随天马，勾选“全量覆盖”才重建其他来源管理字段；两种模式都保留 UUID、收藏及统计。清除失效条目只修改 TOML，不删除 ROM、原始媒体或此前生成的媒体。默认只为新增入口处理媒体，已有文件不覆盖；全量重新处理全部有效入口媒体。删除游戏、媒体名称或扩展名变化都不清理旧文件，ES-DE 对同名多扩展媒体的实际显示选择需由前端决定。

没有描述文件关联的多个 ISO／CHD 各自导出；已有 M3U／CUE 等只保留最外层已登记入口，被引用的盘文件／轨道不重复登记。官方电脑编辑器将最终幻想8拆成四条，而已保存的 Android 前端数据库中只有一条并指向 Disc 1。用户要求将该差异单独列为待处理，不在本轮引入多盘识别、合盘或 M3U 生成策略；普通多 ROM 版本继续使用上面的命名规则。运行时换盘证据、排序及错误处理状态见 [SaveDeck 待处理清单](PLAN.md#savedeck-待处理事项)。

## 发布保护

加载时记录原天马配置和已有 SaveDeck 配置基线，发布前配置发生变化会停止并要求重新加载。电脑发布复用现有执行器的原子写入与 `.frontendtrans.bak` 首次备份；设备发布备份原配置为 `savedeck.toml.handheldtoolbox.<原指纹>.bak`，通过完整临时文件名 C4 上传后替换。设备失败可能已有部分平台完成，需依据错误重新加载，不宣称整批成功。

## 独立命令行

从源码根目录使用项目环境：

```powershell
& '.\retrolibx\.venv\Scripts\python.exe' -m library_converter scan 'D:\你的游戏库' --to savedeck
& '.\retrolibx\.venv\Scripts\python.exe' -m library_converter convert 'D:\你的游戏库' --to savedeck --platform GBA
```

`--platform` 使用 scan 返回的相对目录，可重复指定。增加 `--full` 对应“全量覆盖”。设备来源增加 `--device`，并将 source 换为当前设备完整 ROM 根目录；只有执行 convert 才发布媒体和配置。SaveDeck 不使用 ES-DE 的 `--shared-media` 迁移选项，不修改天马 metadata 或清理原素材。

引擎入口 `python -m retrolibx.cli convert --to savedeck` 也可生成媒体和配置副本，默认采用相同 SaveDeck 来源 profile；GUI 和上述独立工具入口负责向原平台目录发布。SaveDeck 当前作为导出目标，不提供 SaveDeck 来源导入。
