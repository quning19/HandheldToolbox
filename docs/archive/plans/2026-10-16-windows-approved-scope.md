## Windows 后续待办

2026-10-16 按发布数据表讨论整理为五组：第 6、7、11、15、17/18 项。用户同意第 11、15 项建议及三类手动清理方案，要求汇总实施清单再确认。2026-10-16 用户已批准实施，当前代码见 [结构说明](../../ARCHITECTURE.md)、[主题解析](../../THEME_CONVERSION.md) 和 [工作目录](../../WORKSPACE_DATA.md)。下列为原验收清单；完成状态以本轮记录为准，旧测试记录不覆盖新实现。

### 第 6 项：通用主题解析与动态主题列表

- [ ] 使用通用 ES-DE 主题解析器和统一素材处理策略，逐步替代七套逐主题配置。新主题依据内容解析，不按主题名称选择一套专用配置；新增支持时扩充可复用的语法、引用或素材用途规则。
- [ ] 解析 capabilities.xml、根目录及平台目录 theme.xml、include 引用、嵌套变量、覆盖顺序，以及布局、颜色、字体大小、语言、宽高比等分支；遵循支持的 ES-DE 引擎加载语义。跟踪路径值及其来源，支持目录和文件名都含平台变量、间接变量和带后缀的资源名。
- [ ] 从 XML 实际引用识别图片、视频、动画、字体、平台资料和公共资源。区分主题静态资源与 ES-DE 运行时游戏媒体；按素材用途处理，不对整个主题做平台名称全文替换。
- [ ] 结合统一平台管理中的母体、独立/沿用母体模式、显示名与角标，推导目标所需资源。优先保留目标专用素材，其次继承母体，再按主题自身默认机制回退；生成缺少的平台资料并保留布局、语言和原有元数据。
- [ ] 图片按格式、尺寸、透明度及引用用途采用统一角标策略；公共遮罩、字体、按钮不添加平台角标。SVG、视频及动画默认保持格式、原样继承，不默认转码或丢失动画。用途不明确时保守处理并报告受影响部分，不能声称已完整适配。
- [ ] Canvas、Aura、Alekfull NX、Elementerial、Iconic、iiSU Interpreted、PlayStation-X 的完整真实主题作为覆盖样本：分别关注多素材/配色、多层路径与后缀、自定义资源分支、多层资料及语言、背景与覆盖层、间接变量、平台视频与默认视频。后续测试需单独批准，旧测试通过记录不覆盖新解析器。旧逐主题规则在迁移验证期间保留作对照，不继续作为未来逐主题扩张方案。
- [ ] 初次无工作区主题时列表为空；读取设备或导入本地主题后显示实际条目，包括暂未识别的主题。支持设备原版同步后转换、本地原版直接转换、成功结果上传；原版与转换结果分别保留。不随软件携带完整主题，内置规则不生成七个空条目。
- [ ] 解析缓存由程序生成，源主题或解析器/处理策略版本改变后失效；转换记录包含这些版本，避免升级后把旧结果误认为当前结果。完成迁移后再移除不再需要的逐主题运行配置。

### 第 7 项：完整平台卡片素材与风格切换

- [ ] 平台卡片素材覆盖所选素材类型在来源主题中实际提供的全部平台，不再只保留当前演示使用的 14 张，也不按当前已导入的 ROM 平台裁剪。未来导入其他平台时直接查找对应图片；来源主题未提供的分类不得声称已有专用图。
- [ ] 默认保留 Canvas 风格；额外初选 Aura、Alekfull NX、iiSU Interpreted，分别从其完整平台素材中选择适合矩形网格的清晰展示图。统一的是卡片展示尺寸及缩放策略，保留各套风格本身的区别，不导入无关主题资源。实施时从现有真实主题提取，保留来源记录；随独立软件分发前确认素材分发条件。
- [ ] 设置增加“平台卡片风格”选择，提供上述可用素材集，切换后更新已加载卡片；选择保存到程序同级基础设置，重开保留。此设置独立于亮色/暗色，不改变设备 ES-DE 主题、主题转换对象、游戏封面或业务输出。
- [ ] 同一风格内优先使用对应平台专用图，缺少时使用母体平台图，再使用统一占位；保持平台名称可读，避免将缺图卡片静默混用另一套风格。
- [ ] 完整平台图片作为随包只读资源，用户切换风格仅修改设置，不要求连接设备或同步完整主题。实际资源体积和提取范围在实施时记录，不以当前 14 张预览素材的大小估算未来发布包。

### 第 11 项：默认平台升级与用户配置合并

- [ ] 区分随软件维护的默认平台、用户字段覆盖、用户新增平台以及明确禁用的默认平台，替代当前整份用户列表与新版默认列表彼此独立的状态。内部标识保持稳定，修改显示名称不更换身份。
- [ ] 新版默认平台自动加入，曾被用户明确禁用的除外；用户改过的字段优先，未改字段使用新版默认值，用户新增平台保留。标识或目录冲突时保留用户结果并提示，不静默合并或覆盖。
- [ ] 新版移除的默认平台如果仍被使用或作为母体引用，保留必要定义并提示停止维护；平台管理变更不连带删除 ROM、设备配置或已有主题。
- [ ] 迁移当前整份列表时，存在对应旧版默认表则比较提取用户改动；缺少旧版基线时保守保留现有结果，不猜测用户修改或删除意图。

### 第 15 项：转换结果按实际影响判定过期

- [ ] 生成记录保存原版主题标识/内容依据、与生成有关的平台定义，以及通用解析器和素材处理规则版本。与第 6 项共用解析结果及依赖记录，不另建彼此冲突的状态依据。
- [ ] 原版主题变化、影响展示和资源路径的平台名称/母体/资源标识/角标变化、新增需要生成资源的平台，以及影响输出的解析或素材规则变化，按依赖标记受影响主题需要重新转换。
- [ ] 仅界面、日志、ADB 连接逻辑升级，或切换亮暗模式/平台卡片风格，不使主题结果过期；不按整个软件版本一刀切。无需生成新文件的沿用母体分类不因新增条目本身强制重转。
- [ ] 过期结果保留，列表显示需要重新转换，成功重转前不标为可上传。状态判断使用本地资料，设备已存在状态仍通过明确的刷新操作获取，不为提示反复读取设备大素材。

### 第 17、18 项：三类手动清理与恢复资料分离

- [ ] 设置提供单一“清理工作目录…”入口，窗口只列临时文件、备份与恢复资料、历史日志三类，不另做失败/中断任务功能或分类。默认只勾选临时文件，显示数量、空间和待清理明细后执行所选范围。
- [ ] 按文件用途分类：已完成、失败或中断任务中可重建且不承担恢复作用的索引、预览、中间图片和暂存副本归临时文件；有恢复用途的快照、计划、发布回执和共用素材核对记录，与修改前的文件、旧主题一起归备份与恢复资料。
- [ ] 临时文件放 temp，旧版本及恢复记录按操作批次放 backups，日志放 logs。失败状态不使整批文件自动可删，也不使全部中间文件永久保留；备份和必要回执按关联批次管理。
- [ ] 先完成当前混放文件的分类迁移，迁移时保留恢复引用；人工准备的真实 GBA 样本移到开发样本目录，不纳入清理或独立发布包。无法确认用途的既有文件默认保留，不按 temp 名称整目录删除。
- [ ] 当前运行任务及使用中的文件排除；用户设置、平台定义、当前主题原版、正式转换结果、有效主题状态记录、ROM 和游戏素材排除。手动清理只操作本地工作目录，不触碰设备。
- [ ] 备份与恢复资料默认保留、用户主动选择，最新备份默认不勾选；历史日志保留当前运行日志。首版不做按天自动删除备份。

## 页面与布局

- 两个主业务入口：游戏库转换、主题适配。
- 设置放在侧栏底部，平台管理作为设置内的子页面。
- 设置提供亮色/暗色开关，即时切换并保存在程序同级基础设置；采用蓝紫强调色、青绿完成状态和明确的字体层级。
- Windows 窗口默认横向，操作和当前功能设置集中在列表上方。
- 底部状态栏显示当前设备、连接方式和存储识别信息，不显示工作目录。
- 进度、结果和错误在当前页面显示，不设置独立的任务、对比、报告或历史主页面。

## 软件目录与工作目录

基础设置保存在执行文件同级的 `settings.json`，用于记录整个软件唯一的工作目录及亮暗外观。用户不需要分别设置每项功能的输入、导出或临时目录；其他功能配置和用户数据由工具在工作目录下管理。

```text
工作目录/
├─ config/              平台定义与功能配置
├─ themes/
│  ├─ original/         本地原版主题
│  └─ exported/         完整适配主题
├─ library/             本地游戏库转换产物
├─ devices/             按设备保存的配置快照和操作记录
├─ backups/             旧版本与关联恢复资料（待实现分类迁移）
├─ logs/                日志
└─ temp/                可重建临时文件（当前混放资料待迁出）
```

本地工作目录和设备 ES-DE 工作目录分别管理。设备 ES-DE 目录自动识别，无法唯一确定时才要求选择；媒体位置尊重设备 ES-DE 的 `MediaDirectory`。

## 游戏库转换

### 来源与加载

来源可以是掌机或电脑目录。掌机识别内置存储和 SD 卡，查找 `rom`、`roms` 等目录名，不区分大小写。候选目录只读取直接子目录数量，不在这个阶段递归识别游戏。

切换来源、候选目录或修改电脑路径只更新选择并清空旧平台结果。用户点击“加载平台”后才读取所选来源。检测在后台异步进行，每完成一个平台就向网格追加一张卡片；切换来源时取消旧检测，防止混入旧结果。

掌机输出默认采用内置存储的 ES-DE 目录；电脑转换产物自动进入软件工作目录。常规页面不提供需要用户反复选择的目标目录框。

### 平台卡片与计数

平台采用矩形网格卡片。上部铺满平台插画，当前为 Canvas；完整素材集和设置中切换风格见第 7 项待办。名称以大字居中叠在图上并加描边，选择状态放在角落；下部显示 ROM 数量和封面覆盖数量。各行紧贴卡片内容，行列间距固定。

ROM 数量采用实际存在且能与来源 metadata 对应的独立启动入口：

- 一个游戏有多个独立版本时分别统计、生成多个 gamelist 条目。天马 G 的一张共用封面按各 ROM 名称生成多份 ES-DE 封面。
- 一张多轨光盘按一个描述文件入口统计，其引用的轨道文件不单独计数或生成条目。
- metadata 的缺失引用单独提示，不计入实际 ROM 数量，不阻止存在的 ROM 转换，也不改写源 metadata。
- ROM 没有对应 metadata 时提示未关联资料，不静默遗漏，也不猜测游戏信息。
- 只统计游戏封面是否存在，平台卡片使用的主题图与游戏封面统计互相独立。

### 转换操作

顶部压缩为两行：第一行包含来源、天马 G 目录和加载按钮；第二行包含自动识别的目标位置、共用素材、全量替换和开始按钮。选择数量、ROM 数量及新增数量放在列表标题栏，默认规则不占用多行说明。

默认按平台和 ROM 相对路径与已有 gamelist 比对，仅处理新增入口，已有入口跳过。不做旧素材大小、时间或内容变化判断。

“全量替换”默认关闭，开启后重新处理所选平台当前识别到的全部游戏条目和对应素材；不包含清空目标目录或删除额外条目。共用素材开关独立控制天马 G 和 ES-DE 是否共用转换后的素材。

### ES-DE 配置

没有 `es_systems` 时初始化完整系统定义及其相关四个配置文件，不按本次选择的平台裁剪。已有配置时保留原有节点和用户启动参数，检查所选平台，补齐缺失定义及伴随文件；有歧义时显示问题。无需用户手动执行平台配置维护。

## 主题适配

工作目录内的原版主题和导出主题由工具管理，不分别选择路径。可从当前设备同步原版主题到本地。

执行操作分成同步原版、转换主题和上传主题。转换使用本地原版和统一平台定义，生成完整 ES-DE 适配主题；上传目标自动从设备 ES-DE 目录确定。

列表按主题展示本地原版、转换结果和当前设备适配主题三种状态，能够看出哪些未同步、未转换或可以上传。可上传状态依据实际生成结果判断，不只看目录名称后缀。

“刷新设备主题”读取设备主题目录及必要描述信息，确认对应主题是否存在；不下载整套图片，不计算素材哈希。设备已存在不表示与本地最新输出一致。上传后自动刷新，断开或读取失败时显示未检查或失败，不误标成未上传。

迁移前基线为七套专用适配规则：Canvas、Aura、Alekfull NX、Elementerial、Iconic、iiSU Interpreted、PlayStation-X。本轮按第 6 项迁移为通用解析器，七套主题用作覆盖样本。使用主题全部适用的处理规则，不跟随游戏库本次选择裁剪。新增分类优先采用主题专用素材，缺少时借用母体素材，依据统一素材策略增加 HACK、VIB、HD、MSU1、WARE 等标记。

## 平台管理

游戏库转换与主题适配共用平台定义，支持搜索、手动添加、编辑和删除。先采用本地配置文件，不引入数据库。

基本字段包括显示名称、ROM 目录、母体平台、主题表现及可选角标文字。内部标识和主题资源名自动生成，必要时放到高级信息；默认采用母体启动模板，保留 GBA vib 等专有启动规则。

主题表现分为沿用母体素材和独立分类素材。例如 PSP Minis 可以沿用 PSP，或从 PSP 素材生成独立分类并增加可选的 MINIS 标记。

删除仅移除平台定义，不连带删除 ROM、设备现有配置或已生成主题。仍被其他平台作为母体时提示引用关系。平台登记不等于某个主题已具备全部素材，主题处理仍需依据该主题的适配规则。
