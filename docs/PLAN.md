## 导出结构约定

用户确认保留“共用基础能力、分别组织目标导出流程”的结构：共用 Pegasus 来源解析、媒体查找、通用模型、平台识别、计划／执行器及 ADB 基础发布能力；将可共用的 ROM 入口筛选规则集中复用。ES-DE／SaveDeck 分别负责目标格式、媒体布局、启动配置表达及 XML／TOML 合并，不强行合并两个完整流程。本轮已按确认方案统一入口筛选、增删和全量覆盖，目标格式及发布流程继续分别组织。

### 已实施的更新／删除规则

- 有效入口以所选平台的 metadata 登记、ROM 实际存在及光盘从属关系共同确定；配置或索引读取失败不能当成来源删除。
- 默认模式比较本次有效入口和目标列表：新增入口生成条目及媒体；已失效入口（metadata 删除、ROM 删除、成为从属文件）从目标列表移除；仍有效的已有入口跳过，不顺带更新其资料或媒体。仅新增 ROM 而未登记 metadata 时，不自动补录。
- 全量模式对所选平台全部有效入口重新转换，以本次来源重建、覆盖来源管理的资料、媒体引用和启动命令等字段，并重新处理对应媒体；同样移除已失效入口。全量不再沿用 ES-DE 旧的“已有非空资料仍保留”规则，也不等于清空整个目标目录。
- 两种模式都保留同平台、同 ROM 相对路径的已有入口 UUID、收藏、游玩次数、最后游玩时间等身份及用户使用状态，不被来源默认值覆盖。新入口按目标格式生成标识；路径改名／移动暂不自动识别为同一游戏。
- 删除入口不清理对应媒体，也不删除实际 ROM 或改写原天马 metadata；本次不增加自动媒体清理。已存在的独立共用素材迁移功能不由本次增删流程触发。
- SaveDeck 的配置字段与应用数据库分开：保留 TOML 中已有 ID／用户状态，保持同一入口 ID 稳定，不直接修改应用内部收藏或统计数据库；应用刷新后的状态保留效果不能仅凭配置合并保证，实际验收另按授权范围进行。

本节及 SD-005 已实施，25 个不同最小定向用例取得通过结果。随后完成 15 平台默认模式实机发布及用户验收；本轮没有扩大为全量回归。全量模式、换盘和数据库状态持久化的实机专项检查仍按需另定范围。

## SaveDeck 待处理事项

普通多 ROM 版本的命名已实现：按实际存在的入口计数，仅一个时用 game 名称，多个时用各自 ROM 文件名去扩展名；缺失入口排除。已有 TOML 的名称通过“全量覆盖”刷新，UUID 按 ROM 路径保留。2026-10-19 经用户授权完成 34 项 SaveDeck 定向用例，含命名、媒体路径、版本增删、模拟 ADB 和单个离屏 GUI 用例，结果见 [测试记录](SAVEDECK.md#定向测试2026-10-19)。
