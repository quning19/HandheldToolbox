# Windows 应用界面方案

更新日期：2026-10-15。此方案记录已讨论确定的 Windows 应用页面和业务规则。界面采用 PySide6、Qt Widgets 与 QFluentWidgets 的 Fluent 工作台方向；当前交互原型使用示例数据，尚未接入 Python 业务。

原型源码见 [Fluent 工作台](design/fluent-workspace.html)。原型为对话内演示使用的 HTML 片段；窗口可从右下角调整尺寸，切换页面保持窗口尺寸，超出的列表内容在窗口内滚动。平台图来自现有 Canvas_天马G 主题的 capsule 方形素材，演示仅使用缩略显示副本。

## 页面与布局

- 两个主业务入口：游戏库转换、主题适配。
- 设置放在侧栏底部，平台管理作为设置内的子页面。
- 设置提供亮色/暗色开关，即时切换并保存在程序同级基础设置；采用蓝紫强调色、青绿完成状态和明确的字体层级。
- Windows 窗口默认横向，操作和当前功能设置集中在列表上方。
- 底部状态栏显示当前设备、连接方式和存储识别信息，不显示工作目录。
- 进度、结果和错误在当前页面显示，不设置独立的任务、对比、报告或历史主页面。

## 软件目录与工作目录

基础设置保存在执行文件同级的 `settings.json`，用于记录整个软件唯一的工作目录及亮暗外观。用户不需要分别设置每项功能的输入、导出或临时目录；其他功能配置和用户数据由工具在工作目录下管理。

```text
工作目录/
├─ config/              平台定义与功能配置
├─ themes/
│  ├─ original/         本地原版主题
│  └─ exported/         完整适配主题
├─ library/             本地游戏库转换产物
├─ devices/             按设备保存的配置快照和操作记录
├─ logs/                日志
└─ temp/                临时文件
```

本地工作目录和设备 ES-DE 工作目录分别管理。设备 ES-DE 目录自动识别，无法唯一确定时才要求选择；媒体位置尊重设备 ES-DE 的 `MediaDirectory`。

## 游戏库转换

### 来源与加载

来源可以是掌机或电脑目录。掌机识别内置存储和 SD 卡，查找 `rom`、`roms` 等目录名，不区分大小写。候选目录只读取直接子目录数量，不在这个阶段递归识别游戏。

切换来源、候选目录或修改电脑路径只更新选择并清空旧平台结果。用户点击“加载平台”后才读取所选来源。检测在后台异步进行，每完成一个平台就向网格追加一张卡片；切换来源时取消旧检测，防止混入旧结果。

掌机输出默认采用内置存储的 ES-DE 目录；电脑转换产物自动进入软件工作目录。常规页面不提供需要用户反复选择的目标目录框。

### 平台卡片与计数

平台采用矩形网格卡片。上部铺满 Canvas 平台插画，名称以大字居中叠在图上并加描边，选择状态放在角落；下部显示 ROM 数量和封面覆盖数量。各行紧贴卡片内容，行列间距固定。

ROM 数量采用实际存在且能与来源 metadata 对应的独立启动入口：

- 一个游戏有多个独立版本时分别统计、生成多个 gamelist 条目。天马 G 的一张共用封面按各 ROM 名称生成多份 ES-DE 封面。
- 一张多轨光盘按一个描述文件入口统计，其引用的轨道文件不单独计数或生成条目。
- metadata 的缺失引用单独提示，不计入实际 ROM 数量，不阻止存在的 ROM 转换，也不改写源 metadata。
- ROM 没有对应 metadata 时提示未关联资料，不静默遗漏，也不猜测游戏信息。
- 只统计游戏封面是否存在，平台卡片使用的主题图与游戏封面统计互相独立。

### 转换操作

顶部压缩为两行：第一行包含来源、天马 G 目录和加载按钮；第二行包含自动识别的目标位置、共用素材、全量替换和开始按钮。选择数量、ROM 数量及新增数量放在列表标题栏，默认规则不占用多行说明。

默认按平台和 ROM 相对路径与已有 gamelist 比对，仅处理新增入口，已有入口跳过。不做旧素材大小、时间或内容变化判断。

“全量替换”默认关闭，开启后重新处理所选平台当前识别到的全部游戏条目和对应素材；不包含清空目标目录或删除额外条目。共用素材开关独立控制天马 G 和 ES-DE 是否共用转换后的素材。

### ES-DE 配置

没有 `es_systems` 时初始化完整系统定义及其相关四个配置文件，不按本次选择的平台裁剪。已有配置时保留原有节点和用户启动参数，检查所选平台，补齐缺失定义及伴随文件；有歧义时显示问题。无需用户手动执行平台配置维护。

## 主题适配

工作目录内的原版主题和导出主题由工具管理，不分别选择路径。可从当前设备同步原版主题到本地。

执行操作分成同步原版、转换主题和上传主题。转换使用本地原版和统一平台定义，生成完整 ES-DE 适配主题；上传目标自动从设备 ES-DE 目录确定。

列表按主题展示本地原版、转换结果和当前设备适配主题三种状态，能够看出哪些未同步、未转换或可以上传。可上传状态依据实际生成结果判断，不只看目录名称后缀。

“刷新设备主题”读取设备主题目录及必要描述信息，确认对应主题是否存在；不下载整套图片，不计算素材哈希。设备已存在不表示与本地最新输出一致。上传后自动刷新，断开或读取失败时显示未检查或失败，不误标成未上传。

现有七套适配规则为 Canvas、Aura、Alekfull NX、Elementerial、Iconic、iiSU Interpreted、PlayStation-X。使用所选主题的全部适配规则，不跟随游戏库本次选择裁剪；不承诺任意主题或任意平台均能适配。新增分类优先采用主题专用素材，缺少时借用母体素材，按主题规则增加 HACK、VIB、HD、MSU1、WARE 等标记。

## 平台管理

游戏库转换与主题适配共用平台定义，支持搜索、手动添加、编辑和删除。先采用本地配置文件，不引入数据库。

基本字段包括显示名称、ROM 目录、母体平台、主题表现及可选角标文字。内部标识和主题资源名自动生成，必要时放到高级信息；默认采用母体启动模板，保留 GBA vib 等专有启动规则。

主题表现分为沿用母体素材和独立分类素材。例如 PSP Minis 可以沿用 PSP，或从 PSP 素材生成独立分类并增加可选的 MINIS 标记。

删除仅移除平台定义，不连带删除 ROM、设备现有配置或已生成主题。仍被其他平台作为母体时提示引用关系。平台登记不等于某个主题已具备全部素材，主题处理仍需依据该主题的适配规则。
